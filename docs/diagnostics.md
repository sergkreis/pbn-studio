# Диагностика, производительность и отмена

## Журналы

Основная папка: `%LOCALAPPDATA%/PBNStudio/logs`. Формат — `journal-<run_id>.jsonl` и файлы ротации. При недоступности основной папки приложение пробует `logs` рядом с приложением. Диагностика не должна превращать ошибку записи лога в ошибку пользовательской операции.

По умолчанию журнал включён. Для отключения в PowerShell до запуска:

```powershell
$env:PBN_DIAGNOSTICS = '0'
& ./.venv/Scripts/python.exe launch.py
```

Чтобы вернуть обычное поведение, удалите переменную из текущего окружения или задайте `1` перед новым запуском. Уже запущенное приложение не меняет режим от настройки другого терминала.

Журнал фиксирует действия, этапы, длительности, типы ошибок и ограниченные координаты стеков; фильтрация исключает содержимое изображений/проектов и чувствительные поля. Это не повод прикладывать все файлы без просмотра. Проекты, smoke-отчёты, crash dumps и сторонний stderr могут иметь другую политику содержимого. Перед отправкой удалите личные данные и пути, которые не нужны для воспроизведения.

## Если операция долгая

Зафиксируйте версию, commit/worker hash, размер изображения, параметры, этап и время ожидания. Один профилированный FLUX-прогон занимал около **112 секунд**; это историческое измерение конкретного сценария, не обещание для произвольного входа. Сравнение производительности корректно только на одинаковом разрешённом входе, параметрах и сопоставимой машине; наличие профайлера тоже влияет на время.

«Отменить» устанавливает запрос остановки. Python/domain-операции завершаются на контрольной точке; отдельный Qt/NumPy-вызов может не прерываться посередине. Native worker — отдельный процесс, его можно остановить; это не делает все последующие стадии мгновенно отменяемыми. Закрытие окна ждёт безопасного окончания потока, а не вызывает принудительное уничтожение QThread.

Предыдущий документ должен оставаться неизменным при отмене задания. В пакетном режиме уже опубликованные комплекты сохраняются. Не обещать отмену за фиксированное число миллисекунд и не считать принудительное завершение через диспетчер задач обычным безопасным способом отмены: оно может потерять несохранённые изменения.

## Отчёт об ошибке

Приложите короткое описание, точные шаги, ожидаемое/фактическое поведение, версию и очищенный фрагмент журнала вокруг события. Изображение или проект — только с разрешения правообладателя и пользователя. Для уязвимости используйте [SECURITY.md](../SECURITY.md), а не обычный bug report.
